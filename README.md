# Цифровой деканат «Альтаир»

Учебный концепт конкурса «Цифровой деканат будущего». Академия «Альтаир» вымышлена: люди, оценки, группы и заявления не относятся к РАНХиГС и не являются официальным сервисом университета. Официальные гербы не используются.

Живой стенд: [https://dekanat.213-171-10-37.sslip.io](https://dekanat.213-171-10-37.sslip.io)

## Как проверить за 3 минуты

1. Войти кнопкой «Студент» → нажать ✦ → «что у меня завтра?». Ответ приходит в чате, страница не меняется.
2. «Закажи справку об обучении для военкомата» → карточка → «Подтвердить». В «Заявках» статус «Подана → Готова → Выдана», PDF с QR-кодом.
3. Войти «Преподавателем» → «Журнал» → «какие оценки у Сорокина?» и «поставь Громову 5 за 18.11 по БД». Агент открывает журнал, подсвечивает ячейку и показывает «Было → Станет». Без «Подтвердить» ничего не пишется, после — есть «Отменить».
4. «Поставь оценку за 21.11» — пары не было, агент откажет и предложит ближайшие прошедшие пары.

После проверки, пожалуйста, отменяйте тестовые оценки кнопкой «Отменить».

## Что умеет кабинет

- **Студент:** главная, расписание на день и неделю с переносами и отменами, успеваемость в накопительных баллах и прогресс к автомату, задания и сдача работ, заявки и справки со статусом и PDF, уведомления, профиль.
- **Преподаватель:** журнал «студенты × колонки» с баллами и явкой по периодам, выданные задания со счётчиком «Сдали X из Y», проверка работ с вкладками и фильтрами, своё расписание с переносами.
- **Учебный офис:** входящие заявления, смена статуса с уведомлением студенту, объявления.
- **Агент:** отвечает на вопросы по данным, ставит оценку и явку (в том числе всей группе одной карточкой), создаёт задание, заказывает справку. Не ставит оценку на дату без пары. Каждое официальное действие — через карточку подтверждения с «Было», с отменой через журнал.

## Главное: локальный агент

Агент — центр кабинета, а не боковая справка. Студент, преподаватель и сотрудник учебного офиса говорят с ним обычными фразами: «что у меня завтра», «закажи справку об обучении для военкомата», «поставь 5 Сорокину за лабу».

Модель только предлагает вызов инструмента. Факты, права и запись в базу делает сервер.

- В браузере, если есть WebGPU, работает WebLLM (Qwen2.5). Веса качаются один раз и остаются на устройстве. Оценки в облако не уходят.
- Свой сервер можно подключить через `LOCAL_LLM_URL` (Ollama или llama.cpp, OpenAI-совместимый API). Это не основной путь.
- Если модели нет, фразу разбирает детерминированный разборщик. Облачные LLM по умолчанию выключены (`ENABLE_CLOUD_LLM`).
- Один реестр действий, `shared/src/registry.ts`, обслуживает и экраны, и агента. Схема на zod, роли зашиты в инструмент.
- Чтение выполняется сразу. Обратимое действие можно отменить. Официальное (заявление, оценка, возврат работы, смена статуса) ждёт одну карточку подтверждения и только потом пишется.
- Инструмент не принимает `userId` и `studentId`: человек берётся из сессии. Чужой объект — 404.
- Журнал «что делал агент» хранит шаги. Неподтверждённая карточка через 10 минут помечается «Не подтверждено».

Подробнее: [docs/architecture.md](docs/architecture.md), [docs/PROMPTS.md](docs/PROMPTS.md), [docs/security.md](docs/security.md).

## Стек

- Интерфейс: React, Vite, TypeScript, Tailwind, Radix, TanStack Query, Framer Motion.
- Сервер: Fastify, Drizzle, PostgreSQL. Один процесс в production отдаёт собранный интерфейс и `/api`.
- Контракт: общий пакет `shared` (реестр, разбор фраз, даты по Москве).
- PDF справок: pdf-lib и встроенный Noto Sans (кириллица, лицензия OFL).

## Безопасность

- Пароли — scrypt (N=16384, r=8, p=1). На неверный логин считается такой же хеш, ответ один.
- Сессия — случайный токен в httpOnly-cookie. В базе хранится только хеш. Мутации требуют CSRF и свой Origin.
- Вход ограничен: 8 попыток на пару IP+логин и 64 на IP за 10 минут (ответ 429).
- Студент не читает чужие заявки, работы и журнал. Преподаватель видит только свои группы. Сотрудник не открывает преподавательские действия, и наоборот.
- Текст заявлений и регламентов — данные. Его не исполняют. В учебном положении есть фраза-ловушка, она остаётся цитатой.
- В бланке справки нет номера зачётки. Публичная проверка по коду отдаёт только то, что и так напечатано на бланке.

## Запуск локально

Нужны Node.js 22 и PostgreSQL 16.

Postgres можно поднять контейнером:

```bash
docker run -d --name altair-pg \
  -e POSTGRES_USER=dekanat \
  -e POSTGRES_PASSWORD=dekanat \
  -e POSTGRES_DB=dekanat \
  -p 5432:5432 postgres:16
```

Дальше обычный npm, без Docker:

```bash
cp .env.example .env
npm install
npm run db:migrate
npm run db:seed
npm run db:seed:homework
npm run db:seed:schedule-extend
npm run dev
```

Кабинет: http://127.0.0.1:5317  
API: http://127.0.0.1:4317  

`npm run db:seed` пересоздаёт демо-пользователей. На базе, которую жалко стирать, его не запускают: достаточно `npm run db:migrate` и идемпотентного `npm run db:seed:homework`.

Проверки:

```bash
npm test
npm run typecheck
```

Боевая сборка одним процессом Node описана в [DEPLOY.md](DEPLOY.md). Туда же вынесены Caddy, `COOKIE_SECURE` и `TRUST_PROXY`.
